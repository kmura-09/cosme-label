# 成分表ジェネレーター (cosme-label)

原料 (商品名) とその INCI 構成比を登録し、処方 (原料 × 配合%) から化粧品の
**全成分表示の記載順**を作る、ブラウザ内で完結する静的 Web アプリ。
GitHub Pages でそのまま動き、サーバーにデータを送りません。

- **原料登録**: 商品名 / メーカー / INCI ごとの原料中 % / 表示名称 (日本語) / 着色剤フラグ。
  CSV・JSON で取込と書出。データはブラウザの localStorage に保存。
- **成分登録**: INCI ↔ 表示名称の辞書 (自分で育てる)。初回は基本成分 300 件
  (`data/starter_ingredients.csv`、市販原料でよく使われる順) が自動で入り、お手元の
  成分表示名称リストの CSV (「INCI名」「表示名称」列) を読み込めば増やせる。
- **成分表生成**: 原料を配合% で並べる (コピペ入力可) と、INCI ごとに合算して
  **降順 / 1% 以下は順不同帯 / 着色剤は末尾** の規則で記載順を出力。表示名称と INCI の
  1 行テキストをコピー。由来原料と寄与% を表示。
- **訴求点の候補**: 成分辞書の配合目的・由来・天然由来率から、「〇〇（保湿剤）配合」「植物由来成分
  N 種配合」、ISO 16128 の考え方による自然由来指数 (水を含む / 除く、未登録分は幅で表示)、表示できる
  フリー表示を候補として出す。文言の採用可否は利用者の判断。
- **訴求文の LLM 生成**: 上記の事実をまとめたプロンプトを作り、手持ちの LLM に貼るか、利用者自身の
  Anthropic API キーでブラウザから Claude を直接呼んで商品説明の下書きを作る (化粧品モードでは
  効能効果 56 項目の範囲に収める指示付き)。サーバーは介さず、キーはブラウザにだけ保存。
- **規制チェック**: EU 1223/2009 Annex、化粧品基準 (告示331号)、KFDA、21 CFR 352 由来の
  配合上限・禁止 (595 行、`data/regulatory_limits_inci.json`) と突き合わせ。剤型・地域
  未指定時は最も緩い上限を採用。

扱わないもの: 香料一括表記、キャリーオーバー成分の省略、医薬部外品の表記順などの法規判断。
規制は改正されるので、最終的な表示は担当者が最新原文で確認してください。

## 使い方

1. 「原料登録」タブで「サンプル原料を読込」(33 件) を押すか、自分の原料を登録する。
2. 「成分表生成」タブで処方を貼り付ける (1 行 1 原料「原料名 配合%」)。
   `data/sample_formula_shampoo.txt` / `data/sample_formula_cream.txt` が例。
3. 右に成分表が出る。

### CSV の列

`name, inci_name, pct` が必須。任意で `display_name, is_colorant, maker, note`。
1 行 = 1 原料の 1 成分 (縦持ち)。同名原料は上書き。

## ローカルで動かす

ES module を使うので `file://` では動かない。何かで配信する:

```bash
python3 -m http.server 8000   # → http://localhost:8000
```

## テスト

`test/golden.json` に処方 → 成分表、テキスト解析、規制引き当ての期待値をまとめてあり、
ロジック (`js/label.js`) がそれと一致することを検証する:

```bash
node test/run.mjs
```

## 構成

```
index.html            画面 (3 タブ: 成分表生成 / 原料登録 / 使い方)
js/label.js           純ロジック (合算・並び順・テキスト解析・規制引き当て・突合)
js/store.js           原料マスタ (localStorage、CSV/JSON 取込・書出)
js/csv.js             CSV パーサ / シリアライザ
js/app.js             画面の配線
data/                 規制 JSON、サンプル原料 CSV、サンプル処方
test/                 期待値 (golden.json) と検証スクリプト (run.mjs)
```
